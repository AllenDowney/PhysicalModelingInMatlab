# PhysicalModelingInMatlab

The repo for *Physical Modeling in MATLAB*, 4th edition, by Allen Downey (Green Tea Press): LaTeX source in `book/` (`make` builds `PhysicalModelingInMatlab4.pdf`; `make distrib` copies it to the root and commits it), code for each chapter in `code/chapNN/`, data in `code/data/`. Readers download `PhysicalModelingInMatlab.zip` (linked from the book via `book/links/urls.csv`). Book page: <https://greenteapress.com/wp/physical-modeling-in-matlab/>.

- `sh build.sh` rebuilds `PhysicalModelingInMatlab.zip` (a curated subset of `code/`, listed in the script); rerun it and commit the ZIP after changing any of those files (CI fails if it's out of date).
- Releasing a version: build the PDF (`make` in `book/`) and the ZIP (`sh build.sh`), commit both at the root, then `gh release create vX.Y.0` with both as assets (`PhysicalModelingInMatlab4.pdf`, `PhysicalModelingInMatlab.zip`). Allen deploys the PDF's copy on greenteapress.com (GreenTeaPress `scripts/deploy_gtp.sh`). The book's ZIP link (`greenteapress.com/matlab/zip`) redirects to the ZIP on `master`.
- Work is tracked in `PROJECT_BOARD.md`; plans go in `planning/`.
- Task 1 is a refresh; the guide is the "Refresh checklist" in `~/GreenTeaPress/plans/workshops.md`, adapted for a MATLAB book (Octave instead of Python and Colab).
- Test: `tests/run_tests.sh` (all chapter code, in Octave, on a copy of `code/`; cases in `tests/cases.txt`) and `python3 tests/test_notebooks.py` (the chapter notebooks, including that each intentional error fails with the message the notebook shows); same in CI. Code examples should run in both MATLAB and GNU Octave. Run them on a copy of `code/`: some scripts write the book's figures to `../../book/figs/`. Octave is not installed system-wide; use the mamba env `PhysicalModelingInMatlab` (`mamba run -n PhysicalModelingInMatlab octave …`).
- Keep `master` as the default branch (links in the book point to it).
- GitHub Pages (since 2026-11-01) serves `site/dist`: the Jupyter Book at the root (the chapters as web pages, from `site/jb/`; Task 3) and the JupyterLite site in `run/` (Octave in the browser, with the chapter code; Task 2), deployed by `.github/workflows/site.yml` with Pages source "GitHub Actions", so only `site/dist` is published, not the repo's `.md` files. Keep it that way (don't switch Pages to a branch). Build locally with `site/build.sh` in an env from `site/build-environment.yml`. Chapter notebooks (`site/notebooks/chapNN.ipynb`, committed) are generated from the LaTeX: build the book (`make` in `book/`, for `main.aux`), then `python site/tex2nb.py N book/main.aux site/notebooks/chapNN.ipynb`; per-chapter edits (calls to add, static blocks, exercise solutions from `code/`) go in `site/notebooks/chapNN.json`. Don't hand-edit the `.ipynb`. The committed notebook is the solution version; `site/remove_soln.py` makes the student version at build time. On the site both are in the chapter folder (`chapNN/chapNN.ipynb`, `chapNN/chapNN_soln.ipynb`), so they can call the chapter's scripts. After changing a notebook or a chapter's code, run `python site/run_notebooks.py` locally (in the `PhysicalModelingInMatlab` env) and commit `site/jb/chapNN.ipynb`: the Jupyter Book's notebooks with outputs (CI fails if they're out of date; `--check`). The book build (`site/jb/prep_notebooks.py`, at build time) adds the run links and hides solutions. Bugs in the browser Octave go in `planning/upstream_issues.md`.
